SECTION 1 — PROJECT OVERVIEW
────────────────────────────────────────────────────────────────────────

Build a web-based SaaS platform called "AdForge" — an AI-powered video
ad creation studio purpose-built for performance marketers, e-commerce
founders, and growth agencies.

Unlike existing tools, AdForge is a COMPLETE end-to-end ad production
pipeline. It is not just a video generator. It covers the full lifecycle:

  IDEA → SCRIPT → ACTOR → GENERATE → EDIT → EXPORT → PUBLISH

Every competitor stops at GENERATE. We do not.

The platform solves the following verified pain points of the current
market leader (and all competitors):

  PAIN POINT 1: No built-in editor. Solved. We build the editor.
  PAIN POINT 2: No free trial. Solved. Freemium model from day one.
  PAIN POINT 3: Hidden pricing. Solved. Fully transparent pricing page.
  PAIN POINT 4: Weak script tools. Solved. Full AI script studio.
  PAIN POINT 5: Credit caps feel punishing. Solved. Subscription by
                 seat + output minutes, not per-video credits.
  PAIN POINT 6: Top of funnel only. Solved. Retargeting script variants
                 and post-click landing page copy generation included.
  PAIN POINT 7: No physical product interaction. Solved. Product overlay
                 engine with depth-mapped actor-product compositing.
  PAIN POINT 8: No campaign structure. Solved. Full campaign workspace
                 with hook variants, angle tracking, and test logging.

5.1 — AI SCRIPT STUDIO (THE #1 DIFFERENTIATOR VS. COMPETITORS)

  Build a multi-step script generation interface:

  STEP 1: BRIEF INPUT
    Input fields:
    - Product/service name
    - One-line description
    - Target audience (who are they? what do they want?)
    - Primary pain point being solved
    - Target platform (TikTok / Meta / YouTube / etc.)
    - Desired tone (dropdown: Friendly / Urgent / Playful / Educational
                    / Authoritative / Emotional / Humorous)
    - Ad objective (dropdown: Awareness / Clicks / App Install /
                   Purchase / Lead Gen / Retargeting)
    - Video length target (15s / 30s / 60s / 90s)

  STEP 2: AI GENERATES 3 COMPLETE SCRIPT VARIANTS
    Each variant includes:
    - Hook (opening 3 seconds — the scroll-stopper)
    - Body (problem + solution narrative)
    - CTA (specific, platform-appropriate)
    - Angle label (e.g. "Pain Point Agitation", "Social Proof",
      "Before/After", "Curiosity Gap", "Authority Play")
    - Estimated watch-through rate prediction label
      (High / Medium / Low — based on known patterns)

  STEP 3: HOOK EXPANDER
    User can click any variant and generate 5 alternative hooks
    for the same script body. This solves the "I want to test 5
    different openers with the same script" use case in 10 seconds.

  STEP 4: RETARGETING VARIANT (GROWTH + AGENCY PLANS)
    One-click: "Generate retargeting version of this script"
    Produces a script assuming the viewer has already seen the
    original ad — speaks to familiarity, pushes urgency/proof.

  STEP 5: LANDING PAGE COPY BLOCK (GROWTH + AGENCY PLANS)
    After script approval, generate matching above-the-fold
    landing page copy:
    - Headline
    - Subheadline
    - 3 bullet benefits
    - CTA button text
    Ensures message match between ad and landing page — a huge
    performance lever that zero competitors address.

5.3 — VIDEO GENERATION ENGINE

  When the user submits a generation job:

  1. API Route receives job parameters
  2. Inngest job is queued immediately
  3. UI shows real-time status via Supabase Realtime subscription
     (no polling — websocket updates: Queued → Processing → Complete)
  4. Inngest worker:
     a. Sends script text + actor ID + voice ID to ElevenLabs
        → returns audio file (stored in Supabase Storage)
     b. Sends audio file + actor reference to Hedra API
        → returns lip-synced video file
     c. If B-Roll enabled: sends scene prompts to Runway ML
        → returns b-roll clips
     d. If Product Overlay enabled: sends product image through
        Replicate depth-compositing pipeline
        → composites product into actor's hands/body
     e. All assets assembled via FFmpeg (serverless FFmpeg via
        Cloudflare Workers or AWS Lambda)
     f. AssemblyAI transcription if captions enabled
        → burned-in captions with customisable font/style/position
     g. If music enabled: Epidemic Sound track selected by mood
        tag, ducked under voice using FFmpeg audio filter
     h. Final video uploaded to Supabase Storage → CDN via
        Cloudflare → outputUrl written to Ad record in DB
  5. Supabase Realtime fires status update → UI refreshes

  Generation time target: < 3 minutes for a 60-second ad.

5.4 — BUILT-IN VIDEO EDITOR (THE BIGGEST GAP IN THE MARKET)

  After generation, user enters the Editor. Built on Fabric.js +
  custom video timeline layer.

  EDITOR CAPABILITIES:

  TIMELINE (bottom panel):
  - Drag-and-drop clip ordering
  - Trim handles on each clip (drag start/end points)
  - B-Roll clip insertion at any point on timeline
  - Music track lane (separate from voice track)
  - Caption track lane

  CANVAS (centre):
  - Video preview at target aspect ratio
  - Overlay text layers (drag to position, resize, restyle)
  - Logo/watermark layer (upload PNG, drag to position)
  - Sticker/emoji overlay layer
  - Progress bar overlay option (trendy UGC pattern)

  RIGHT PANEL — STYLE CONTROLS:
  - Caption style selector (Bold/Minimal/TikTok/Gradient/Outline)
  - Caption font selector (Google Fonts integration)
  - Caption position (top / middle / bottom)
  - Caption animation (Pop / Fade / Word-by-Word)
  - Music volume slider
  - Voice volume slider
  - Video brightness/contrast/saturation sliders
  - Vignette toggle

  RIGHT PANEL — TRANSITIONS:
  - Cut / Fade / Zoom / Swipe (between clips)

  EXPORT PANEL:
  User selects output formats before export:
  ☑ 9:16 Vertical (TikTok / Reels / Shorts)
  ☑ 1:1 Square (Feed)
  ☑ 16:9 Landscape (YouTube / LinkedIn)

  All selected formats generated simultaneously in one export job.
  Delivered as a zip file or individual download links.

  The editor state (Fabric.js JSON) is saved to the Ad.editState
  field in the DB so users can return and re-edit at any time.

5.5 — CAMPAIGN WORKSPACE & A/B TEST TRACKER

  Inside each Campaign, the user sees:

  SCRIPT MATRIX VIEW:
  ┌──────────────┬──────────────┬──────────────┬──────────────┐
  │              │  Actor 1     │  Actor 2     │  Actor 3     │
  ├──────────────┼──────────────┼──────────────┼──────────────┤
  │  Hook A      │  [Video ✓]   │  [Video ✓]   │  [Queued...] │
  ├──────────────┼──────────────┼──────────────┼──────────────┤
  │  Hook B      │  [Generate]  │  [Video ✓]   │  [Generate]  │
  ├──────────────┼──────────────┼──────────────┼──────────────┤
  │  Hook C      │  [Generate]  │  [Generate]  │  [Generate]  │
  └──────────────┴──────────────┴──────────────┴──────────────┘

  Click any cell → preview that ad, download, or launch generation.
  This is the creative testing matrix that agencies dream about.

  PERFORMANCE LOG (manual entry — no ad platform API in MVP):
  User can log performance data against each ad:
  - CTR %
  - Hook Rate (3-second view rate) %
  - ROAS
  - Platform (where it ran)
  - Notes
  
  Over time this builds an internal learning database per account
  that feeds the AI script generator — "write scripts in the style
  of my best-performing angles." Post-MVP feature, but the data
  structure must be built now.

5.6 — PRODUCT OVERLAY ENGINE

  User uploads:
  - Product image (PNG with transparent background, or JPG — we
    auto-remove background via Replicate remove-bg model)
  - Optionally: App screenshot (for "Show Your App" mode)

  System composites the product into the AI actor's scene using
  depth-map estimation to place product naturally in front of
  the actor's hands. Not a simple overlay — it respects scene depth.

  Modes:
  - HOLD IT: Product in actor's hands (physical product)
  - WEAR IT: Apparel overlay on actor's body (fashion brands)
  - SHOW IT: Phone screen showing app/website in actor's hand
  - BEHIND IT: Product shown large in background behind actor

5.7 — MULTILINGUAL ENGINE

  - Select target language before generation (30+ via DeepL)
  - Script is translated by DeepL BEFORE sending to ElevenLabs
    (translation → TTS, not TTS → dubbing — this is more accurate)
  - Actor filtered to native speaker of target language where
    available in our library
  - Captions auto-generated in target language
  - UI shows "Native Speaker Available" badge when a matching
    actor exists for the selected language
